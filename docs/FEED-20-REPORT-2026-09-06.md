Written 2026-09-06 from a read-only investigation of the repo, the committed feed snapshots for the last six runs (`frontend/build-data/feed.json` at commits 917e34c, 23376d0, 518d449, 729e3fb, 6c64add, 7c10f6e), the two most recent Actions pipeline logs (runs 33969878783 and 34037912432), the Actions run history for the deploy and verify workflows, and the live page. ## Part A: four findings outside the brief that change its premises

### A1. The holistic re-rank (step 8c) has written zero rows since at least 2026-08-11

Both the 09-05 and 09-06 run logs end step 8c with `Done. 0/N clusters re-ranked ... (N rows NOT confirmed written)` after 24 to 29 lines of `[err] Bulk upsert chunk failed after retries: NOT NULL constraint failed: story_clusters.title`. Cause: `rerank.py` upserts partial rows (id, headline_rank, rank_world and a few more) and the SQLite shim issued a single `INSERT ... ON CONFLICT(id) DO UPDATE` over the payload columns. SQLite, like Postgres, checks `title TEXT NOT NULL` on the candidate insert row before the conflict arbiter runs, so every chunk failed. Independent proof from the data: across all 500 rows in five snapshots, stored `headline_rank == round(5 + 0.95 * importance_score, 2)` with zero violations, which is step 7's soft-floor rescale; a landed re-rank would make the two columns equal. The run summary still printed `Errors: 0` because that line counted RSS fetch errors only.

Consequence: a continuing cluster keeps the rank it was born with, so maturity and longevity never update and the day's biggest continuing stories can sit at base rank 28 with 67 to 77 sources (the diesel-price story, two days running).

Fixed on this branch: the shim now applies PostgREST merge semantics (update the supplied columns of an existing key, insert a new key, never reset `created_at`); unconfirmed re-rank writes are recorded on `pipeline_runs.errors` and the summary line reads `Errors: N fetch, M pipeline`.

### A2. Clustering Phase 7 (same-event merge) was enabled, contaminated, and dropped the absorbed articles

CLAUDE.md said Phase 7 was disabled. Commit 82c240c disabled it and 436ec8d re-enabled it 1h49m later; `main.py` calls `cluster_stories` with defaults, so it ran every day. The logs show it fusing "IDF strikes Hezbollah" with two "Russian drone strikes Ukraine's SBU" clusters, "Iran War Day 189" with "Gas prices", a Tesla Cybercab probe with "Alcaraz, Sabalenka into US Open last 16", and the Putin 72-hour pause with a judge's order and Trump's "small potatoes" remark. It also updated `articles` and `source_count` but never `article_ids`, and step 8 writes `cluster_articles` from `article_ids`: survivors shipped an inflated source_count and the absorbed articles vanished. On 09-06, 4 of 100 exported clusters had `source_count` above their link count (76 on 40 links for the Putin story, 50 on 33 for the Iran tanker, 46 on 26 for the Nepal rescue, 31 on 17 for the Williams sisters).

Fixed on this branch: Phase 7 is off by default (`enable_same_event_merge=False`), an insert-time tripwire warns when `article_ids` and `articles` disagree, and same-event merging moves to the Stage 2 candidate pass.

### A3. The served-output gate detects the tail URLs but had not run since 09-04

`check_href_shape` fires on `/?story=` (confirmed against the live page: 3 malformed hrefs, exit 1). The verify workflow only triggered on `workflow_run` of the deploy. Every deploy since 09-04 19:13 UTC was the scheduled 15:00 or 17:00 backstop, and no verify run followed any of those five deploys; the last verify run was 09-04 02:16. When it did run (08-31 to 09-04) it failed 11 of 15 times, each appending to issue #4 (26 comments) with no follow-up.

Fixed on this branch: scheduled verify backstops at 15:30 and 17:30 UTC, and the same script runs as the last step of the deploy job so a bad served page turns the deploy run red.

### A4. The two-model tier is already gone and the flash cap is a request cap

Since 2026-08-11 step 8d sends every summary to `gemini-2.5-flash` in graduated batches (schedule 1, 1, 4, 8, 10, 10, 10, 6: eight requests for 50 stories); `flash_top_n` is documented in the code as inert, and main.py's "top-10 flash, rest flash-lite" log line was stale. The flash limit is 20 requests per day, so "20 stories on flash" costs about five requests. Step 7b is 30 sequential flash-lite calls whose rows 8d never cache-hits (0 hits on 09-06, 4 on 09-05) because the cache requires the flash tier. The comment claiming a 20 per day flash-lite cap was wrong: the 09-05 run made 44 flash-lite requests with no 429.

## Part B: the reports

### B1. Tail URL bug (Block 1b)

A second divergence: the print archive's real-summary test did not mirror the frontend's `cleanFeedSummary` emptiness test (no `isRawExcerpt`, no CSAM exemption), so a printed card the frontend dropped shifted the window by one more. ### B3. Lean stability at 20 (Block 4b)

Per-article lean scores from the committed deepdive files, six runs. Within-cluster standard deviation is 12 to 14 at every rank; the difference between bands is sample size.

| band | scored articles (median) | SE of avg_political_lean (median) | max SE |
|---|---|---|---|
| top 20 | 21 to 37 | 2.0 to 3.1 | 4.6 to 6.3 |
| ranks 21 to 50 | 10 to 15 | 2.0 to 4.2 | 8.3 to 13.0 |

Derived floor: at sd 12.5, SE <= 4 (a 10-point 7-band width is 2.5 SE) needs 10 scored articles; SE <= 3 needs 17. The lean label is suppressed when `lean_measured_count < 10`, a derived number rather than a guessed one. The 55/42 split of one event across two cards is a merge problem, not a floor problem.

The Greek jet at Right on 23 sources is not sampling noise (n = 26, SE 2.6). Seventeen articles sit at exactly 50 with confidence 0.15 to 0.70; four sit at 65 and five at 80 to 90 (Breitbart, NY Post, GB News, NTD, Just The News) with confidence 0.15, meaning the outlet baseline is the only signal on a story with no political text. The rigor-weighted mean lands at 60. This is the engine's "both outlet and text" blend producing baseline drift on apolitical wire stories. Option for the CEO: when mean article confidence is below 0.4, label "No tilt measured" instead of a direction. It needs the bias fixture suite and is not implemented here.
