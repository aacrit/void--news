B · Dev/prod & safety net

infra

Your daily pipeline writes the same database the public reads. Before strangers arrive: a staging surface, a backup, and a lock on main.

auto

Cloudflare auto-builds non-production branches to a stable preview URL. This becomes your "see it before it's public" surface.

manual

CF dashboard → Pages → void-news → Settings → Environment variables → Preview. Add NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, NEXT_PUBLIC_BASE_PATH = "" (empty), NEXT_PUBLIC_DISABLE_AUDIO. Preview shares one env scope across all non-prod branches — that's expected.

The staging preview URL loads live data.
manual

Right now a direct push to main deploys instantly with no gate. Repo → Settings → Branches → add a rule for main → require status checks: build-check, validate-bias, validate-clustering. Keep auto-merge working by allowing the checks it already runs.

A push that fails a check can no longer reach the live site.
auto

A scheduled GitHub Action that dumps the Supabase DB and stores the artifact, so a bad migration or pipeline run during the experiment is recoverable.

manual

The backup client was fixed to postgresql-client-17 (the server is Postgres 17.6; every earlier run failed on a version mismatch). Run it and prove recovery: Actions → Nightly DB Backup → Run workflow, download the db-backup artifact, then restore it into a throwaway Postgres to confirm it is real: gunzip -c backup-*.sql.gz | psql <scratch-db-url>. (Claude can dispatch the run; the restore is yours to do once.)

DB size is fine now: ~272 MB, ~54% of the 0.5 GB cap and shrinking (retention works). The old "near the cap" warning is stale. Egress note: a full dump is ~272 MB read from Supabase; the free tier allows ~5 GB egress/month, so a nightly full backup (~8 GB/mo) would exceed it. Consider running the backup weekly (plus the automatic pre-migration dumps) to stay in budget.

A downloaded dump restores cleanly into a scratch DB.
manual

The pipeline, deploy, and backup now alert on failure, and a daily check flags a stale feed, but only once a webhook is wired. Without this you are flying blind.

Discord: a server → Server Settings → Integrations → Webhooks → New Webhook → pick a channel → Copy Webhook URL, then append /slack to the end of that URL (Discord accepts Slack-format payloads at that suffix). Slack: create an Incoming Webhook and copy its URL as-is.

Add it as a repo secret named ALERT_WEBHOOK_URL: Repo → Settings → Secrets → Actions → New secret. Until it is set, the alert steps no-op safely.

A deliberately-failed run posts a message to your channel.

05

D · App stores (iOS + Android)

longest lead time

The shells are already built (Capacitor, appId void.news). Android builds on your Windows machine; iOS needs a Mac, so it routes through a cloud build. Start the accounts early — they gate everything else.

manual

developer.apple.com/programs/enroll. Enrollment/identity check can take 24-48h — do it first.

manual

play.google.com/console/signup.

manual

iOS builds need macOS + Xcode, which you don't have. Recommended: Codemagic — cloud Mac, native Capacitor support, auto-signs with an App Store Connect API key and publishes to TestFlight. Alternatives: a GitHub Actions macOS runner, or a rented/borrowed Mac. Connect the repo once decided.

A cloud macOS build of the iOS shell succeeds once.
auto

npx cap sync android, set versionCode/versionName, wire the signing config to read from the keystore + secrets.

manual

keytool -genkey -v -keystore void-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias void. Back it up offline in two places. Lose it and you can never update the app again.

manual

Build a signed AAB → Play Console → Internal testing track → invite your friends by email. This is the fastest way to get the real app into hands (minutes, not review days). Promote to production later.

auto

npx cap sync ios, confirm a store-legal reverse-DNS bundle id (e.g. com.void.news), and add the Codemagic build config.

manual

Create an App Store Connect API key, hand it to Codemagic for automatic code signing. Register the app id + create the app record in App Store Connect.

manual

Distribute the build to TestFlight and invite friends by email — no public listing, no full review. This is your iOS "friends beta" and it sidesteps App Store review timing entirely.

manual

manual

Apple privacy nutrition label + Google Data Safety. Simple here: no accounts, no tracking. Disclose the feedback form's free text and the rate-limit fingerprint; point both at /privacy.

manual

Android review ~hours; Apple ~1-2 days. Apple may push back under Guideline 4.2 ("just a web view") — the rebuttal is the daily brief, audio, offline reading, and share target: real app value, not a bookmark. TestFlight/internal-testing already cover friends regardless of review timing.
